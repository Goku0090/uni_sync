PROJECT OVERVIEW
═══════════════════════════════════════════════════════════════════════════════

UniSync is a full-stack Django web application designed to connect university
students for collaborative project work. It provides user profiles, project
discovery, social features, real-time messaging, and team management.

TECH STACK
─────────────────────────────────────────────────────────────────────────────
Backend:        Django 4.2.8 + Django REST Framework 3.14.0
Database:       PostgreSQL (production) / SQLite (development)
Real-time:      Django Channels 4.0.0 + Redis
Email:          Brevo, ZeptoMail, Gmail SMTP (with fallback chain)
Auth:           Django Allauth (social OAuth + traditional login)
Caching:        Redis 5.0.1
Task Queue:     Celery 5.3.4
Storage:        AWS S3 (boto3)
Frontend:       Django Templates + HTML/CSS/JavaScript
Deployment:     Gunicorn + Render/Railway

CODEBASE SIZE
─────────────────────────────────────────────────────────────────────────────
- Main app: accounts/ (3000+ lines of views + 700+ lines of models)
- URL patterns: 130+ endpoints
- Database models: 15+ core models
- REST API endpoints: 50+ endpoints
- Templates: 20+ HTML templates
- Static files: CSS, JS, images
- Configuration: settings.py (356 lines)

KEY ARCHITECTURE DECISIONS
═══════════════════════════════════════════════════════════════════════════════

1. OTP AUTHENTICATION
   - Reason: No password storage burden, SMS-like UX
   - Implementation: Django OTP model with 5-minute expiry
   - Fallback: Traditional password authentication available

2. MULTI-BACKEND EMAIL
   - Reason: Reliability and cost optimization
   - Implementation: Auto-fallback chain in settings
   - Backends: Brevo → ZeptoMail → Gmail → Console

3. DJANGO ALLAUTH
   - Reason: Robust social auth, battle-tested
   - Features: Google, GitHub OAuth, email verification
   - Configuration: Customizable signup forms

4. DJANGO CHANNELS
   - Reason: Real-time WebSocket support
   - Use cases: Messaging, notifications, typing indicators
   - Fallback: Polling for older browsers

5. CELERY + REDIS
   - Reason: Async task processing
   - Use cases: Email sending, NLP analysis, notifications
   - Fallback: Synchronous execution in dev

6. POSTGRESQL
   - Reason: ACID compliance, JSON support
   - Features: Arrays for interests/skills, full-text search ready
   - Fallback: SQLite for development

GETTING STARTED (Quick Steps)
═══════════════════════════════════════════════════════════════════════════════

1. CLONE REPOSITORY
   git clone https://github.com/Goku0090/uni
   cd auth_project

2. SETUP ENVIRONMENT
   python -m venv venv
   source venv/bin/activate  # or venv\Scripts\activate (Windows)
   pip install -r requirements.txt

3. CONFIGURE
   cp .env.template .env
   # Edit .env with your settings (email, social auth, etc.)

4. INITIALIZE DATABASE
   python manage.py migrate
   python manage.py createsuperuser  # Create admin user

5. RUN SERVER
   python manage.py runserver
   # Visit http://localhost:8000

6. ACCESS ADMIN
   # Visit http://localhost:8000/admin
   # Use superuser credentials
