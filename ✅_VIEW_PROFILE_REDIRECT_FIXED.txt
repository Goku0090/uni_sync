THE PROBLEM
═════════════════════════════════════════════════════════════════════════════

Issue:
  When users clicked the "View Profile" button on collaborator cards in the
  Find Collaborators Enhanced template, they were redirected to the main home
  page instead of loading the user's profile page.

Expected Behavior:
  Click "View Profile" → Load /user/{username}/ → Show user profile

Actual Behavior (Before Fix):
  Click "View Profile" → Load /user/{username}/ → Exception occurs
  → Redirect to main home → User confused ❌

Location:
  Template: find_collaborators_enhanced.html (line 696)
  View: accounts/views.py - user_profile() function (line 2607)
  URL Pattern: path('user/<str:username>/', views.user_profile, name='user_profile')


ROOT CAUSE ANALYSIS
═════════════════════════════════════════════════════════════════════════════

The Problem:
  The user_profile() view had overly broad exception handling:
  
  try:
      # View logic
  except Exception as e:
      return redirect('main_home')  # ❌ Catches ALL exceptions

This was Too Broad:
  • Catches ANY exception from ANY code in the try block
  • Could be UserStats issue, Activity issue, or query issue
  • Always redirects instead of attempting to render profile
  • Hides the actual error from user
  • No graceful degradation

Specific Issues It Hides:
  1. UserStats.DoesNotExist - User might not have stats yet
  2. Activity filter error - Query filtering on potentially missing fields
  3. Follow model issues - Relationship queries failing
  4. Any unexpected error - No information why

Result:
  ❌ Users redirected to home
  ❌ Profile never loaded
  ❌ No error message
  ❌ Confusing user experience


THE SOLUTION
═════════════════════════════════════════════════════════════════════════════

File Modified:
  accounts/views.py (lines 2607-2698)

Approach:
  1. Handle specific exceptions explicitly (UserStats.DoesNotExist)
  2. Add try-except for Activity queries with fallback
  3. Instead of redirecting, render profile with available data
  4. Log errors for debugging
  5. Graceful degradation - show basic profile if advanced features fail

Key Changes:

1. UserStats Handling (Before):
   user_stats, created = UserStats.objects.get_or_create(user=profile_user, defaults={})
   
   UserStats Handling (After):
   try:
       user_stats = UserStats.objects.get(user=profile_user)
       if (timezone.now() - user_stats.last_updated).total_seconds() > 300:
           user_stats.update_stats()
   except UserStats.DoesNotExist:
       user_stats = UserStats.objects.create(user=profile_user)
       user_stats.update_stats()

2. Activity Filtering (New):
   try:
       activities = Activity.objects.filter(
           user=profile_user, is_public=True
       ).select_related(...)
   except Exception:
       # Fallback without is_public filter
       activities = Activity.objects.filter(
           user=profile_user
       ).select_related(...)

3. Exception Handling (Before):
   except Exception as e:
       return redirect('main_home')

   Exception Handling (After):
   except Exception as e:
       logger.error(...)
       # Render basic profile with available data
       return render(request, 'social/user_profile.html', context)
