Authentication

Session Authentication

For web applications using Django sessions. Login through the web interface and your session will be maintained for API calls.

# Your browser session handles authentication automatically # No additional headers needed for web app usage

Token Authentication

For mobile apps and external integrations. Obtain a token and include it in your requests.

curl -X GET "{{ api_base_url }}user-stats/" \ -H "Authorization: Bearer YOUR_API_TOKEN" \ -H "Content-Type: application/json"

Basic Authentication

For testing and development. Send username and password with each request.

curl -X GET "{{ api_base_url }}user-stats/" \ -u "username:password"

Error Handling

Common HTTP Status Codes

200 Success - Request completed successfully
201 Created - Resource created successfully
400 Bad Request - Invalid request parameters
401 Unauthorized - Authentication required
403 Forbidden - Insufficient permissions
404 Not Found - Resource doesn't exist
500 Server Error - Internal server error

Error Response Format

{ "error": "Detailed error message", "code": "ERROR_CODE", "timestamp": "2025-11-03T17:50:00Z" }

Rate Limiting

Limits

Authenticated Users 1000 requests/hour
Unauthenticated Users 100 requests/hour
File Uploads 50 MB/hour

Rate Limit Headers

X-RateLimit-Limit: 1000 X-RateLimit-Remaining: 999 X-RateLimit-Reset: 1635960000 X-RateLimit-Retry-After: 3600

When you exceed the rate limit, you'll receive a 429 (Too Many Requests) status code with a Retry-After header indicating when you can make requests again.
