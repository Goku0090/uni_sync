Step 1: Add CSRF token helper function
───────────────────────────────────────
function getCsrfToken() {
    let token = document.querySelector('meta[name="csrf-token"]')?.getAttribute('content');
    if (token) return token;
    const name = 'csrftoken';
    if (document.cookie) {
        for (let cookie of document.cookie.split(';')) {
            cookie = cookie.trim();
            if (cookie.startsWith(name + '=')) {
                return decodeURIComponent(cookie.substring(name.length + 1));
            }
        }
    }
    return document.querySelector('[name=csrfmiddlewaretoken]')?.value || null;
}

Step 2: Add CSRF token to fetch headers
───────────────────────────────────────
const csrftoken = getCsrfToken();

fetch(`/accounts/send-connection-request/${userId}/`, {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'X-CSRFToken': csrftoken,  ← ADD THIS LINE
        'X-Requested-With': 'XMLHttpRequest'
    },
    body: JSON.stringify({})
})

Step 3: Test it
───────────────
F12 → Console → getCsrfToken() → Should return a string

If returns "null" → CSRF token missing from page
If returns "abc123..." → Working correctly

Step 4: Verify server response
───────────────────────────────
F12 → Network → Click Connect → Check POST request
Should see: 200 OK (not 403 Forbidden)

═══════════════════════════════════════════════════════════════════════════════
                          WHY THIS HAPPENS
═══════════════════════════════════════════════════════════════════════════════

Django has CSRF (Cross-Site Request Forgery) protection enabled by default.

Requirements for POST requests:
  1. CSRF token must exist on page (already there)
  2. Token must be sent in request header (MISSING!)
  3. Token must match what Django expects (will match once sent)

When header is missing → Django rejects → 403 Forbidden
