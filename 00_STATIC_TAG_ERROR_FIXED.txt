                        HOW DJANGO TEMPLATES WORK

Basic Template Structure:
┌────────────────────────────────┐
│ {% load static %}              │ ← Required to use {% static %}
│ {% load humanize %}            │ ← Load other template libs as needed
│                                │
│ <!DOCTYPE html>                │
│ <html>                         │
│   <head>                       │
│     <img src="{% static ... %}" │ ← Now this tag is recognized
│   </head>                      │
│ </html>                        │
└────────────────────────────────┘

The {% load %} Directive:
  • Must be at top of template
  • Makes template libraries available
  • Common ones:
    - {% load static %}     - for static files
    - {% load humanize %}   - for text formatting
    - {% load socialaccount %} - for social auth

Without {% load static %}:
  ❌ Django doesn't recognize {% static %} tag
  ❌ Throws TemplateSyntaxError
  ❌ Page breaks

With {% load static %}:
  ✅ Django recognizes {% static %} tag

================================================================================
                        WHY THIS HAPPENS
================================================================================

When Django template parser sees:
  <img src="{% static 'images/logo.jpg' %}">

It needs to know what "static" means. The parser checks:
  1. Is "static" in the list of loaded template tags?
  2. If NO → TemplateSyntaxError
  3. If YES → Process the tag and replace with URL

The {% load static %} directive registers the static tag library.

Common Django Errors:
  • {% static %} used without {% load static %}
  • {% url %} used without {% load %}
  • {% render_form %} used without {% load widget_tweaks %}
  • etc.

Solution Always:
  Add {% load <library> %} at top of template
